## How I like to build

- **Measure before polishing.** A benchmark beats a confident demo.
- **Make failure a designed state.** Retries, refusals, and recovery paths belong in the architecture.
- **Keep the clever parts inspectable.** Traces, tests, citations, and plain-language trade-offs.
- **Leave the system easier to understand.** Good engineering should reduce mystery.
